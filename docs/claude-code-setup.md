# Claude Code setup

How DealPilot is configured for Claude Code, and how the team works with it.

## Files

| File | Purpose | Committed |
| --- | --- | --- |
| `CLAUDE.md` | Project context, stack, architecture decisions, conventions, testing strategy, do's/don'ts | Yes |
| `docs/PRD.md`, `docs/architecture.md` | Imported into CLAUDE.md with `@` | Yes |
| `.claude/settings.json` | Shared permission rules | Yes |
| `.claude/settings.local.json` | Personal permission overrides | No |
| `CLAUDE.local.md` | Personal notes (sandbox URLs, test accounts) | No |

## Permissions

Rules in `.claude/settings.json` are enforced by Claude Code, not by the model. Evaluation order is deny → ask → allow, so a deny always wins.

- **Allow (no prompt):** read-only and routine commands: lint, typecheck, tests, Prisma generate/validate/migrate dev, local git (status, diff, log, branch, add, commit), and docs sites for the stack.
- **Ask (prompt every time):** anything that changes dependencies, shared history or infrastructure: `npm install`, `git push`, merge, rebase, `gh pr`, edits to `package.json`, `prisma/schema.prisma` and `.github/`.
- **Deny (blocked):** reading or editing `.env*`, editing applied migrations and design mockups, `rm -rf`, force push, `git reset --hard`, production deploys, `curl`/`wget`, `sudo`.

Check active rules in a session with `/permissions`.

## CLAUDE.md iteration with /init

1. On the fresh Next.js + Prisma scaffold, run `/init` and commit the result unchanged:
   `docs(claude): add CLAUDE.md generated by /init`
2. Review what /init found (build commands, stack) and what it could not know (ranking rules, TDD, security, design source of truth).
3. Replace it with the full CLAUDE.md, keeping /init's correct commands, and commit:
   `docs(claude): add architecture decisions, conventions, TDD and do's/don'ts`
4. Keep iterating: when Claude repeats a mistake or a review catches something, add one line and commit with `docs(claude): …`.

The diff between commits 1 and 3 is the evidence of iteration.

## Context management

| Situation | Command |
| --- | --- |
| Starting a new, unrelated task | `/clear` |
| Long session, keep only what matters | `/compact keep the plan, failing test names and open TODOs` |
| Resume yesterday's work | `claude --continue` (latest) or `claude --resume` (pick one) |
| Check what is loaded | `/context` |

Durable context lives in files, not chat: plans in `docs/plans/`, rules in `CLAUDE.md`. `DESIGN.md` is referenced by path instead of imported, so UI context loads only for UI tasks.
